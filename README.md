# 🐧 펭구 줌인 Pro v1.3 (Pengu Zoom Pro v1.3)

본 프로젝트는 지인으로부터 전달받은 `펭구 줌인 1.3.exe` 파일의 컴파일된 바이트코드를 성공적으로 디스어셈블하여 복원해 낸 전체 소스코드 프로젝트 패키지입니다.

## 🛠️ 개발 환경 설정 및 실행 방법

소스코드를 실행하려면 다음 라이브러리들이 필요합니다.

### 1. 필수 라이브러리 설치
터미널(Cmd 또는 PowerShell)을 열고 아래 명령어를 실행하여 필요한 패키지들을 설치합니다.
```bash
pip install -r requirements.txt
```

### 2. 프로그램 실행
라이브러리 설치가 완료되면 아래 명령어로 화면 돋보기 프로그램을 실행할 수 있습니다.
```bash
python magnifier.py
```

## ⌨️ 펭구 줌인 사용 방법
1. **화면 확대 및 축소**: `Ctrl` 키를 누른 상태에서 **마우스 휠**을 굴려 배율을 조절합니다 (`1.0x ~ 20.0x`).
2. **마우스 따라오기 토글**: `Ctrl` + **마우스 휠 클릭**을 누르면 마우스 커서를 돋보기가 쫓아다니게 하거나, 그 자리에 고정되게 토글할 수 있습니다. (설정에서 단축키 변경 가능)
3. **특정 영역 고정 확대 (Select Area)**: 좌측 상단의 `Select Area` 버튼을 클릭한 뒤, 모니터 상에서 확대해 두고 지켜볼 영역을 드래그하여 선택합니다 (듀얼모니터 환경을 지원합니다).
4. **단축키 설정**: `Set Follow Hotkey` 버튼을 누르고 `Ctrl+F1` 등 원하는 단축키 조합을 누르면 해당 키 조합으로 따라오기 토글 키가 변경됩니다.
5. **창 크기 조절**: 돋보기 창의 우측 하단 모서리를 마우스로 드래그하면 크기를 유동적으로 바꿀 수 있습니다.
6. **프로그램 종료**: 창의 `✕` 버튼을 누르거나, 키보드의 `ESC` 키를 누르면 안전하게 종료됩니다.

## 🟣 보스 디버프 감지 — 암흑 수류탄 (신규)

보스 체력바 아래 **디버프 칸 줄**을 OpenCV로 감시해서, 지금 상대 중인 보스에게 암흑 수류탄
디버프가 걸려 있는지와 몇 초 남았는지를 **파티 현황창 맨 위**에 표시합니다.

### 왜 칸 하나가 아니라 줄 전체를 잡는가
디버프 칸은 디버프가 늘거나 사라질 때마다 가운데 정렬로 다시 배치되어 **좌우로 움직입니다**
(제공된 두 스크린샷에서도 같은 디버프가 x=930과 x=926에 있었습니다).
그래서 칸 좌표를 고정하지 않고, 줄 전체를 한 번에 캡처한 뒤 그 안에서 아이콘을 매 프레임 찾습니다.
아이콘 크기는 16~46px 범위로 훑기 때문에 해상도·UI 배율이 달라도 동작합니다.

### 우측 하단 배틀 아이템 칸과 혼동되지 않는 이유
같은 아이콘이 단축키 칸에도 보이지만, 감지 영역이 보스 체력바 아래 줄로 제한되고
단축키 칸 쪽 아이콘은 일치율이 0.52~0.61에 머물러 기본 임계값 0.80을 넘지 못합니다.

### 사용 방법
1. `설정 → 보스 디버프` 탭을 엽니다.
2. `자동 추정`으로 기본 위치를 잡거나, `영역 지정`을 눌러 보스 체력바 아래 디버프 줄을
   드래그로 선택합니다. 이때 **숫자(남은 초)까지 포함**되도록 살짝 아래까지 잡아 주세요.
3. `암흑 수류탄 디버프 감지 사용`을 켜면 파티 현황창 위에 배너가 나타납니다.
4. 파티 연동 중이면 감지 결과가 파티원에게도 공유되어, 보스를 못 보고 있는 사람도 확인할 수 있습니다.

### 남은 시간 표시 방식
인게임 숫자는 1080p 기준 **높이 8px**입니다. 숫자를 4배로 확대한 뒤 **네 가지 채널**
(살몬색 warm, 색조 거리, 밝기 top-hat, 밝기 bottom-hat)로 각각 후보를 만들고,
글자 배치가 `N초` 답게 생긴 후보만 남겨 그중 하나를 고릅니다. 채널을 하나만 쓰면
용암·석양처럼 배경이 글자보다 더 붉은 보스방에서 배경 얼룩을 숫자로 착각하는데,
그것이 "이 보스에서는 되는데 저 보스에서는 안 된다"의 원인이었습니다.

그래도 글자를 분리하지 못하면 **상관 정합**으로 다시 읽습니다. 이진화를 거치지 않고
학습해 둔 글자 외형을 화면에 직접 맞추는 방식이라, 배경이 글자와 같은 색 계열로
물들어도 동작합니다. 실측에서 붉은 배경 프레임 판독률이 15% → 100%로 올랐고,
한 캐스트 안에서 숫자가 거꾸로 흐르는 모순은 14.9% → 2.1%로 줄었습니다.

표본이 흔들려도 틀린 값을 보여주지 않도록 아래 우선순위로 동작합니다.

| 표시 | 근거 |
|---|---|
| `OCR` | 학습된 숫자 글리프로 직접 읽은 값 (앞뒤가 맞는 두 프레임이 필요) |
| `자동 보정` | 숫자가 2자리 → 1자리로 바뀌는 순간이 정확히 9초라는 점을 이용한 보정 |
| `추정` | 설정한(또는 자동 학습한) 총 지속시간에서 경과 시간을 뺀 값 |
| `ON` | 디버프는 걸려 있지만 남은 시간을 확정할 수 없는 상태 |

번들 글리프 프로파일은 실측 프레임 57장으로 학습(leave-one-out 정확도 0.998)되어
설치 직후부터 숫자 인식이 켜집니다. 다른 해상도에서 숫자가 어긋날 때만 `숫자 샘플 수집`을
켜고 암흑 수류탄이 **사라질 때까지** 한 번 둔 뒤 `샘플로 숫자 학습`을 누르세요.
라벨은 디버프가 사라진 시점에서 역산되고, 학습 결과의 정확도가 낮으면 채택되지 않습니다.
자세한 내용은 `boss_debuff_assets/README.md` 를 참고하세요.

`추정`에 쓰이는 총 지속시간은 **여태 읽은 가장 큰 숫자**로 자동 학습되고, 설정 탭에
현재 학습값이 표시됩니다. 값이 실제보다 길게 굳어 디버프가 걸릴 때마다 엉뚱한 숫자가
스치면 `학습값 초기화`를 누르세요(다음 캐스트에서 다시 배웁니다). 지속시간을 직접
입력하면 그 값이 학습값보다 우선합니다.

## 🐧 기동 인트로 (신규)

앱이 켜질 때 펭구 마스코트가 점프해 등장하고, 손을 두 번 흔들고, 눈을 깜빡이고
윙크한 뒤 고개를 숙여 인사하고 사라지는 2.41초짜리 인트로가 투명 창에
재생됩니다. 재생 중 **클릭이나 ESC로 즉시 건너뛸 수 있고**,
`설정 → 표시 옵션 → 시작할 때 마스코트 인트로 보여주기` 로 끌 수 있습니다.

### 왜 영상이 아니라 프레임 시퀀스인가
Qt의 `QMediaPlayer`/`QVideoWidget` 는 알파를 보존하지 않아, 투명 배경 영상을
띄우면 캐릭터 뒤에 검은 사각형이 남습니다. 그래서 알파가 있는 PNG 프레임을
투명 창 위에 `QPainter` 로 직접 그립니다.

### 그림 12장으로 움직이는 방법
그림은 **실루엣이 바뀌는 순간만** 담습니다(날개 각도 3단, 눈 3단, 벌린 입,
날개 모음, 인사). 나머지는 코드가 만듭니다.

| 코드가 만드는 것 | 방법 |
|---|---|
| 점프 궤적 | `dy` 를 올렸다 내림. 상승 `out_cubic` / 하강 `in_quad` 라 위에서 느려지고 아래에서 빨라짐 |
| 웅크림·착지 반동 | `squash`(세로 배율). 발바닥을 앵커로 잡아 눌릴 때 땅에 붙어 보임 |
| 몸 기울기 | 손을 들 때 `rot` 로 3도 기울여 무게를 실음 |
| 퇴장 | 살짝 커지며 페이드 |

생성 모델에 24장을 요구하면 칸마다 캐릭터가 미세하게 달라져 재생 시 떨림으로
보입니다. 이 구조는 그 위험 없이 중간 동작을 만듭니다.

### 프레임 정규화
원본 시트는 칸마다 캐릭터 위치가 흔들립니다(실측: 배 중심 x가 최대 20px,
발바닥이 행마다 30px 차이). `tools/build_intro_frames.py` 가 **발바닥 기준선**과
**배 타원 중심·폭**을 기준으로 모든 프레임을 한 캔버스에 다시 얹습니다. 배 타원은
날개를 들거나 펼쳐도 변하지 않아 포즈에 흔들리지 않는 척도입니다.

다만 웅크린 프레임은 배가 **일부러** 넓어져 있어, 그 폭에 맞춰 줄이면 스쿼시가
지워집니다. 그래서 배 폭이 중앙값에서 8% 이상 벗어난 프레임은 변형으로 보고
중앙값 기준 배율을 줍니다. 배율은 항상 1.0 이하만 쓰고, 고DPI 화면에서는 물리
픽셀 기준으로 상한을 한 번 더 낮춥니다.

알파 없이 **초록 배경으로 온 시트도 그대로 받습니다**. 녹색이 다른 채널을 넘는
양으로 알파를 만들고, 경계에 남는 녹색 물듦(spill)은 그 초과량만큼 깎습니다.
despill 을 생략하면 어두운 배경에서 캐릭터 외곽에 초록 테가 보입니다.

새 시트로 교체할 때:
```bash
py tools/build_intro_frames.py --sheet intro_assets/새시트.png --cols 4 --rows 3
py design_preview/verify_intro.py       # 타임라인을 한 장으로 붙여 눈으로 확인
py design_preview/render_intro_gif.py   # 실제 속도로 재생되는 GIF (컷 길이 판단용)
py tests/test_intro_animation.py        # 정렬·타임라인·건너뛰기 검사
```

컷 길이는 정지 컷 시트로는 판단할 수 없어 GIF로 A/B 비교해서 정했습니다. 공중
정점에 60ms 머물러 체공감을 주고, 윙크는 250ms 유지해 표정이 읽히게 하고, 손
흔들기는 컷당 90~110ms로 뒀습니다. 이 세 값은
`tests/test_intro_animation.py` 가 되돌아가지 않게 검사합니다.

## ⏱️ 스킬 쿨타임 자동 학습 (신규)

등록한 스킬을 쓰면 슬롯에 뜨는 남은 초(`17s`)를 읽어 **그 스킬의 쿨타임 총량을
스스로 알아냅니다.** 쿨타임을 직접 입력하지 않은 스킬이 자동으로 채워집니다.
`설정 → 표시 옵션 → 스킬 쿨타임 자동 학습 사용` 으로 끌 수 있습니다.

### 왜 '실시간 판독'이 아니라 '총량 학습'인가
v2.46에서 걷어낸 옛 구조는 15Hz로 매 프레임 숫자를 읽어 그 값으로 카운트다운을
굴렸습니다. 한 프레임만 실패해도 화면 숫자가 튀었고, 스킬 아이콘은 직업·단축키마다
다르니 실패가 잦았습니다.

쿨타임 총량은 스킬마다 **고정된 상수**입니다. 한 번만 알아내면 그 뒤는 기존 수동
카운트다운이 그대로 표시합니다. 그래서 필요한 것은 매 프레임 정확도가 아니라
한 번의 확실한 값이고, 판독은 **캐스트 직후 2초만** 돌아갑니다(평상시 부하 0).

근거는 두 갈래로 재서 서로 검증합니다.

| 근거 | 방법 | 성격 |
|---|---|---|
| `ocr` | 숫자를 읽어 `총량 = 읽은 값 + 캐스트 후 경과 시간` | 2초 안에 학습 |
| `ready` | 사용 직후부터 다시 사용 가능해질 때까지의 시간 | 오독 위험 0, 한 바퀴 관찰 필요 |

`ocr` 은 **두 판독이 경과 시간과 일관되게 줄어들 때만**(3초 뒤에 3초 줄었다) 후보로
삼고, 후보는 **서로 다른 사용에서 두 번** 같아야 확정됩니다. 쿨감(각인·장비)으로
값이 짧아지는 것도 같은 조건으로 받아들입니다.

### 배경은 학습할 수 없다 — 그래서 배경을 만들어 시험한다
스킬 아이콘은 직업·단축키마다 달라 표본을 모을 수 없습니다. 학습 대상은 배경이
아니라 **글자 모양**이고, 그건 실측 41장(`cooldown_assets/samples`)으로 완비됩니다
(0~9 전부 등장). 배경 불변성은 아래 구조로 확보했습니다.

| 실측 사실 | 활용 |
|---|---|
| 획 밝기 V 218~239 (배경과 무관하게 일정), 채도 S 0~8 | `achro` 채널: 밝고 무채색인 획만 남긴다 |
| 배경은 어둡거나(V 26~80) 고채도(S 152~188) | 그 결합이 1차 단서가 된다 |
| 흰색·연회색 아이콘에서는 글자가 배경보다 **어둡다** | `dark`·`median_neg` 채널이 반대 극성을 담당 |
| 숫자 12~13px, `s` 9px, 베이스라인 편차 1px, 간격(advance) 0.61~0.94 | 배치 검사로 헛것을 버린다 |

임계값은 고정 스윕이 아니라 그 프레임의 가장 진한 획에서 유도하고, 채널 x 임계값
9~15가지 중 **두 가지 이상이 같은 값을 낼 때만** 채택합니다. 배경 무늬가 만든
우연한 후보는 다른 조합에서 재현되지 않습니다.

옛 엔진이 슬롯 전체를 프로파일 크기(45x43)로 리사이즈했던 것도 제거했습니다.
사용자가 드래그한 ROI는 실측 42x39~48x49로 제각각이라 글자가 찌그러졌습니다.
지금은 슬롯을 그대로 두고 **찾아낸 글자만** 12x16 캔버스로 정규화합니다.

글자 판정은 HOG 최근접이 아니라 **평균 모양과의 정규화 상관**입니다. 실측에서
slotA로 배운 모양과 slotB 글자의 HOG 거리는 정답이어도 4.5~5.0(채택 상한 3.2)이라
전부 거부됐지만, 상관으로 보면 정답 0.90~0.99 / 2등 0.63~0.75로 확실히 갈립니다.

### 실측 성적 (`tools/eval_cooldown_ocr.py`)

| 시험 | 정확 | 오독 |
|---|---|---|
| 실측 41장 | 39/40 (1장 거부) | **0** |
| 슬롯 교차 (slotA로 학습 → slotB 판독) | 10/10 | **0** |
| 슬롯 교차 (slotB → slotA) | 30/30 | **0** |
| 합성 적대 배경 429장 | 305 (71%) | **0** |
| 쿨타임 끝난 슬롯(숫자 없음) | — | **0** |

합성 적대 배경은 실측 글자의 획을 알파째로 떼어내 밝은 주황·순백·연회색·고주파
질감·그라데이션·광택 얼룩 위에 얹은 것입니다. 통과 조건은 정확도가 아니라
**오독 0건**입니다. 값을 못 읽으면 다음 사용에서 다시 학습하면 되지만, 틀린 값은
파티 전체에 잘못 전파되기 때문입니다. 한 프레임 처리 비용은 20ms 안쪽이고,
캐스트 직후 2초 동안 5Hz로만 돌아갑니다.

### 프로파일을 다시 만들 때
```bash
py tools/build_cooldown_profile.py     # cooldown_assets/samples -> profiles/skill_cooldown.json
py tools/eval_cooldown_ocr.py          # 실측 LOO + 슬롯 교차 + 합성 적대 배경
py tests/test_cooldown_reader.py       # 오독 0건 회귀 검사
```
학습 후 leave-one-out 정확도가 프로파일에 기록되고, 0.90 미만이면 채택되지
않습니다(라벨이 오염된 학습을 막습니다). 현재 번들 프로파일은 0.977입니다.

> 1분을 넘는 쿨타임의 표기 형식(`65s` / `1:05` / `1m 5s`)은 아직 확인하지
> 못했습니다. 파서는 1~3자리 `Ns` 만 받고, 그 밖의 형태는 **값을 내지 않습니다**
> (틀린 값을 내는 것보다 안전). 해당 스킬 슬롯 캡처가 생기면 넓힐 수 있습니다.

## 📦 다시 단일 실행파일(.exe)로 빌드하기
빌드 정의는 `pengzoom.spec` 한 곳에 모여 있습니다. 동봉할 데이터 파일, 숨은 import,
제외 모듈, 실행파일 이름(`magnifier.py`의 `APP_VERSION`에서 자동으로 따옵니다)이
모두 스펙에 기록되어 있어 누가 빌드해도 같은 결과가 나옵니다.

### 1. PyInstaller 설치
```bash
pip install pyinstaller
```

### 2. 빌드 실행
```bash
pyinstaller --noconfirm pengzoom.spec
```
`dist/펭구 줌인 <버전> Pro.exe` 하나가 생성됩니다.

보스 디버프 아이콘 템플릿(`boss_debuff_assets/icons`)과 숫자 글리프
프로파일(`boss_debuff_assets/timer_profiles`), 쿨타임 OCR 프로파일(`ocr_profiles`),
쿨타임 글리프 프로파일(`cooldown_assets/profiles`), 인트로 프레임(`intro_assets/frames`)은 스펙이 이미 동봉하므로 `--add-data` 를
따로 붙일 필요가 없습니다. 동봉 누락은 `tests/test_build_spec.py` 가 검사합니다.

### 3. 기동 실패를 진단할 때
`--windowed` 빌드는 stdout/stderr가 사라져서 원인을 볼 수 없습니다.
콘솔이 붙은 진단용 바이너리를 만들려면:
```bash
set PENGZOOM_DEBUG_CONSOLE=1
pyinstaller --noconfirm pengzoom.spec
```
