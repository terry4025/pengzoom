# 🐧 펭구 줌인 Pro v1.3 (Pengu Zoom Pro v1.3)

본 프로젝트는 지인으로부터 전달받은 `펭구 줌인 1.3.exe` 파일의 컴파일된 바이트코드를 성공적으로 디스어셈블하여 복원해 낸 전체 소스코드 프로젝트 패키지입니다.

---

## 🛠️ 개발 환경 설정 및 실행 방법

소스코드를 실행하려면 다음 라이브러리들이 필요합니다.

### 1. 필수 라이브러리 설치
터미널(Cmd 또는 PowerShell)을 열고 아래 명령어를 실행하여 필요한 패키지들을 설치합니다.
```bash
pip install -r requirements.txt
```

### 2. 프로그램 실행
라이브러리 설치가 완료되면 아래 명령어로 화면 돋보기 프로그램을 실행할 수 있습니다.
```bash
python magnifier.py
```

## ⌨️ 펭구 줌인 사용 방법
1. **화면 확대 및 축소**: `Ctrl` 키를 누른 상태에서 **마우스 휠**을 굴려 배율을 조절합니다 (`1.0x ~ 20.0x`).
2. **마우스 따라오기 토글**: `Ctrl` + **마우스 휠 클릭**을 누르면 마우스 커서를 돋보기가 쫓아다니게 하거나, 그 자리에 고정되게 토글할 수 있습니다. (설정에서 단축키 변경 가능)
3. **특정 영역 고정 확대 (Select Area)**: 좌측 상단의 `Select Area` 버튼을 클릭한 뒤, 모니터 상에서 확대해 두고 지켜볼 영역을 드래그하여 선택합니다 (듀얼모니터 환경을 지원합니다).
4. **단축키 설정**: `Set Follow Hotkey` 버튼을 누르고 `Ctrl+F1` 등 원하는 단축키 조합을 누르면 해당 키 조합으로 따라오기 토글 키가 변경됩니다.
5. **창 크기 조절**: 돋보기 창의 우측 하단 모서리를 마우스로 드래그하면 크기를 유동적으로 바꿀 수 있습니다.
6. **프로그램 종료**: 창의 `✕` 버튼을 누르거나, 키보드의 `ESC` 키를 누르면 안전하게 종료됩니다.

## 🟣 보스 디버프 감지 — 암흑 수류탄 (신규)

보스 체력바 아래 **디버프 칸 줄**을 OpenCV로 감시해서, 지금 상대 중인 보스에게 암흑 수류탄
디버프가 걸려 있는지와 몇 초 남았는지를 **파티 현황창 맨 위**에 표시합니다.

### 왜 칸 하나가 아니라 줄 전체를 잡는가
디버프 칸은 디버프가 늘거나 사라질 때마다 가운데 정렬로 다시 배치되어 **좌우로 움직입니다**
(제공된 두 스크린샷에서도 같은 디버프가 x=930과 x=926에 있었습니다).
그래서 칸 좌표를 고정하지 않고, 줄 전체를 한 번에 캡처한 뒤 그 안에서 아이콘을 매 프레임 찾습니다.
아이콘 크기는 16~46px 범위로 훑기 때문에 해상도·UI 배율이 달라도 동작합니다.

### 우측 하단 배틀 아이템 칸과 혼동되지 않는 이유
같은 아이콘이 단축키 칸에도 보이지만, 감지 영역이 보스 체력바 아래 줄로 제한되고
단축키 칸 쪽 아이콘은 일치율이 0.52~0.61에 머물러 기본 임계값 0.80을 넘지 못합니다.

### 사용 방법
1. `설정 → 보스 디버프` 탭을 엽니다.
2. `자동 추정`으로 기본 위치를 잡거나, `영역 지정`을 눌러 보스 체력바 아래 디버프 줄을
   드래그로 선택합니다. 이때 **숫자(남은 초)까지 포함**되도록 살짝 아래까지 잡아 주세요.
3. `암흑 수류탄 디버프 감지 사용`을 켜면 파티 현황창 위에 배너가 나타납니다.
4. 파티 연동 중이면 감지 결과가 파티원에게도 공유되어, 보스를 못 보고 있는 사람도 확인할 수 있습니다.

### 남은 시간 표시 방식
인게임 숫자는 1080p 기준 **높이 8px**입니다. 숫자를 4배로 확대한 뒤 **네 가지 채널**
(살몬색 warm, 색조 거리, 밝기 top-hat, 밝기 bottom-hat)로 각각 후보를 만들고,
글자 배치가 `N초` 답게 생긴 후보만 남겨 그중 하나를 고릅니다. 채널을 하나만 쓰면
용암·석양처럼 배경이 글자보다 더 붉은 보스방에서 배경 얼룩을 숫자로 착각하는데,
그것이 "이 보스에서는 되는데 저 보스에서는 안 된다"의 원인이었습니다.

그래도 글자를 분리하지 못하면 **상관 정합**으로 다시 읽습니다. 이진화를 거치지 않고
학습해 둔 글자 외형을 화면에 직접 맞추는 방식이라, 배경이 글자와 같은 색 계열로
물들어도 동작합니다. 실측에서 붉은 배경 프레임 판독률이 15% → 100%로 올랐고,
한 캐스트 안에서 숫자가 거꾸로 흐르는 모순은 14.9% → 2.1%로 줄었습니다.

표본이 흔들려도 틀린 값을 보여주지 않도록 아래 우선순위로 동작합니다.

| 표시 | 근거 |
|---|---|
| `OCR` | 학습된 숫자 글리프로 직접 읽은 값 (앞뒤가 맞는 두 프레임이 필요) |
| `자동 보정` | 숫자가 2자리 → 1자리로 바뀌는 순간이 정확히 9초라는 점을 이용한 보정 |
| `추정` | 설정한(또는 자동 학습한) 총 지속시간에서 경과 시간을 뺀 값 |
| `ON` | 디버프는 걸려 있지만 남은 시간을 확정할 수 없는 상태 |

번들 글리프 프로파일은 실측 프레임 57장으로 학습(leave-one-out 정확도 0.998)되어
설치 직후부터 숫자 인식이 켜집니다. 다른 해상도에서 숫자가 어긋날 때만 `숫자 샘플 수집`을
켜고 암흑 수류탄이 **사라질 때까지** 한 번 둔 뒤 `샘플로 숫자 학습`을 누르세요.
라벨은 디버프가 사라진 시점에서 역산되고, 학습 결과의 정확도가 낮으면 채택되지 않습니다.
자세한 내용은 `boss_debuff_assets/README.md` 를 참고하세요.

`추정`에 쓰이는 총 지속시간은 **여태 읽은 가장 큰 숫자**로 자동 학습되고, 설정 탭에
현재 학습값이 표시됩니다. 값이 실제보다 길게 굳어 디버프가 걸릴 때마다 엉뚱한 숫자가
스치면 `학습값 초기화`를 누르세요(다음 캐스트에서 다시 배웁니다). 지속시간을 직접
입력하면 그 값이 학습값보다 우선합니다.

## 📦 다시 단일 실행파일(.exe)로 빌드하기
빌드 정의는 `pengzoom.spec` 한 곳에 모여 있습니다. 동봉할 데이터 파일, 숨은 import,
제외 모듈, 실행파일 이름(`magnifier.py`의 `APP_VERSION`에서 자동으로 따옵니다)이
모두 스펙에 기록되어 있어 누가 빌드해도 같은 결과가 나옵니다.

### 1. PyInstaller 설치
```bash
pip install pyinstaller
```

### 2. 빌드 실행
```bash
pyinstaller --noconfirm pengzoom.spec
```
`dist/펭구 줌인 <버전> Pro.exe` 하나가 생성됩니다.

보스 디버프 아이콘 템플릿(`boss_debuff_assets/icons`)과 숫자 글리프
프로파일(`boss_debuff_assets/timer_profiles`), 쿨타임 OCR 프로파일(`ocr_profiles`)은
스펙이 이미 동봉하므로 `--add-data` 를 따로 붙일 필요가 없습니다.
동봉 누락은 `tests/test_build_spec.py` 가 검사합니다.

### 3. 기동 실패를 진단할 때
`--windowed` 빌드는 stdout/stderr가 사라져서 원인을 볼 수 없습니다.
콘솔이 붙은 진단용 바이너리를 만들려면:
```bash
set PENGZOOM_DEBUG_CONSOLE=1
pyinstaller --noconfirm pengzoom.spec
```

```bash
python tests/test_boss_debuff_detector.py
python tests/test_build_spec.py
```
`tests/` 아래 파일은 표준 `unittest` 기반이라 별도 러너 없이 개별 실행됩니다.
`tests/` 는 패키지가 아니라 `unittest discover` 로는 모이지 않으니, 전부 돌릴 때는
파일을 훑어 주세요 (현재 10개 파일 144개).

```powershell
Get-ChildItem tests\test_*.py | ForEach-Object { py $_.FullName }
```
